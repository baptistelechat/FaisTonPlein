# BLK-004 — COEP `require-corp` bloque silencieusement PostHog

| Friction                                                                                                                                 | Cause réelle                                                                                                                                                                                                                       | Solution                                                                                                                                                                                                                                                       | Statut |
| ---------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| Zéro event PostHog n'arrivait côté serveur malgré une intégration en apparence correcte — aucune erreur visible en usage normal de l'app | `Cross-Origin-Embedder-Policy: require-corp` dans `next.config.ts` (ajouté pour `SharedArrayBuffer`/DuckDB-WASM) bloque toute requête cross-origin no-cors sans header `Cross-Origin-Resource-Policy`, ce que PostHog n'envoie pas | Diagnostic via `posthog.debug()` (log interne "send" sans requête réseau aboutie) + console `net::ERR_BLOCKED_BY_RESPONSE.NotSameOriginAfterDefaultedToSameOriginByCoep`. Bascule COEP en `credentialless` (préserve `SharedArrayBuffer` sans bloquer PostHog) | résolu |
