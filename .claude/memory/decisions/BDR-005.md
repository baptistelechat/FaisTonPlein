# BDR-005 — Projet PostHog partagé avec ifecho via propriété `app`

| Décision                                                                                                                                                                | Pourquoi                                                                                                                                                                | Alternatives considérées                                                                             | Statut |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- | ------ |
| Réutiliser le projet PostHog EU existant (`ifecho`, id `207198`) pour FaisTonPlein, en distinguant les events par une propriété `app: "faistonplein"` / `app: "ifecho"` | Le plan gratuit PostHog limite à 1 projet ; upgrader nécessite une carte bancaire. Baptiste possède déjà ce projet pour ifecho (`C:\Users\DM\Desktop\DEV\perso\ifecho`) | Upgrade payant du plan PostHog (projet dédié isolé), nouveau compte PostHog séparé (email différent) | actif  |

**Conséquences techniques :**

- `posthog.register({ app: "faistonplein" })` ajouté juste après `posthog.init()` côté FaisTonPlein ([src/components/PostHogProvider.tsx](../../../src/components/PostHogProvider.tsx)).
- Même ajout à faire côté ifecho (`posthog.register({ app: "ifecho" })`) pour que le passé et le futur restent cohérents — voir suivi dans le journal.
- Limite assumée : les events **déjà enregistrés** côté ifecho avant ce changement n'auront jamais la propriété `app` (impossible à rétro-appliquer) — seuls les nouveaux events des deux apps seront distinguables.
- Risque RGPD identifié : le projet ifecho a Session Replay actif au niveau projet → FaisTonPlein désactive explicitement `disable_session_recording: true` dans son propre `posthog.init()` pour ne pas en hériter silencieusement.
- Tags de dashboard PostHog (`ifecho`, `analytics`, `v2`) à harmoniser sur tous les dashboards ifecho pour un meilleur filtrage — en attente d'une Personal API Key (édition via l'UI PostHog s'est avérée peu fiable en automatisation navigateur).
