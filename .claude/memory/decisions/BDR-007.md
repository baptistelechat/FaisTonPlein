# BDR-007 — Drift de version pnpm sur le RPi : upgrade global de l'outil plutôt que régénération du lockfile

| Décision                                                                                                                                                                                                                                                                        | Pourquoi                                                                                                                                                                                                                                                                                                              | Alternatives considérées                                                                                                                                                                                  | Statut |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| pnpm du RPi upgradé globalement de 8.15.1 à 10.30.3 (`npm install -g pnpm@10.30.3`, `corepack prepare` sans effet car pnpm était installé via `npm -g` et non via un shim corepack) pour pouvoir installer les dépendances du lockfile `lockfileVersion: '9.0'` généré en local | Le RPi héberge plusieurs autres services `pm2` (newsy, citypaper-worker, calendrier-ligue1-sync) qui partagent le même pnpm global — régénérer un lockfile compatible pnpm 8 aurait créé un écart permanent avec le lockfile du poste de dev (pnpm 10.30.3) et redéclenché le même problème à chaque futur `pnpm add` | `pnpm install --force` pour recréer un lockfile compatible pnpm 8 directement sur le RPi — rejeté : ne résout le symptôme que ponctuellement et fait diverger durablement les deux lockfiles (dev vs RPi) | actif  |
