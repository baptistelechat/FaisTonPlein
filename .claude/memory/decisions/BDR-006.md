# BDR-006 — Isoler les events de test via le filtre `$host` existant (pattern ifecho)

| Décision                                                                                                                                                                                                                        | Pourquoi                                                                                                                                                                                                                                                                                                                                                                          | Alternatives considérées                                                         | Statut |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- | ------ |
| Étendre le filtre PostHog "Internal and test users" (Project Settings > Customization, projet partagé `ifecho`/207198) avec `Host ↛ localhost` (doesn't start with) en plus du `Host ≠ localhost:5173` déjà présent pour ifecho | Baptiste a soulevé le risque de polluer les vraies données en testant (lui ou Claude). Première tentative : propriété custom `test_mode` + code dans `PostHogProvider.tsx`/`analytics.ts` — over-engineering pointé par Baptiste : `$host` est une propriété **native** PostHog déjà auto-attachée à chaque event, ifecho l'utilise déjà pour ce rôle exact, zéro code nécessaire | Propriété custom `test_mode` (rejetée — redondante, plus de code que nécessaire) | actif  |

**Mécanique :** `$host` est auto-capturé par `posthog-js` sur tout event réel (page réelle = vrai domaine). Pour un event envoyé manuellement hors app (API/curl), il suffit de fixer `"$host": "localhost:3000"` dans les properties pour qu'il soit exclu par ce même filtre. `doesn't start with` (plutôt qu'un `≠` exact comme pour ifecho) couvre tous les ports de dev utilisés en local (3000, 3100, 3101…) en une seule règle.

**Gap corrigé au passage :** le beacon manuel de `sessionEnded` (`src/lib/analytics.ts`) contourne le SDK PostHog et n'a donc pas de `$host` auto-attaché — ajouté explicitement (`$host: window.location.host`) pour que ce filtre s'applique aussi à cet event-là.

**Vérifié** : event de test envoyé avec `$host: "localhost:3000"` → absent avec le filtre actif, présent quand désactivé (`filterTestAccounts: false` dans l'URL PostHog). Filtre remis actif après vérification.
