# BDR-008 — Env vars PostHog limitées à l'environnement Production

| Décision                                                                                                                            | Pourquoi                                                                                                                                                                                                                                                                                                                                         | Alternatives considérées                                                                                                                                  | Statut |
| ----------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| Définir `NEXT_PUBLIC_POSTHOG_KEY` et `NEXT_PUBLIC_POSTHOG_HOST` sur le seul environnement **Production** de Vercel, pas sur Preview | Sur Vercel, les builds Preview tournent eux aussi avec `NODE_ENV=production` : le guard de `PostHogProvider.tsx` les laisserait donc envoyer des events. Or le filtre test accounts de [BDR-006](BDR-006.md) n'exclut que les hosts commençant par `localhost` — une preview sort sur `fais-ton-plein-<hash>-…vercel.app` et passerait le filtre | Garder `Preview, Production` (le défaut proposé par Vercel) en étendant le filtre test accounts à un pattern de host preview — plus de config à maintenir | actif  |

**Conséquence :** pour tester l'analytics hors production, ajouter ponctuellement la variable sur Preview, ou passer par `NEXT_PUBLIC_POSTHOG_DEBUG`, déjà prévu dans le code pour activer PostHog hors prod.

**Limite connue :** la production elle-même est servie sur deux hosts — `faistonplein.vercel.app` et l'URL propre à chaque déploiement (`fais-ton-plein-<hash>-…vercel.app`). Toute segmentation future par `$host` doit couvrir les deux.

Voir aussi GLRN-290 (NODE_ENV sur les builds Preview Vercel) en mémoire globale.
