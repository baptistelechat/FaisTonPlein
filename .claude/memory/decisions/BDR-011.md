# BDR-011 — Fallback automatique : reconstruire fuel_history depuis rolling/30days plutôt que repartir à zéro

| Décision                                                                                                                                                                                                                                                                                                                                                                     | Pourquoi                                                                                                                                                                                                                                                                                                                                                                                           | Alternatives considérées                                                                                                                                                                                                                                                                                                                                                                              | Statut |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| `transform.ts` distingue désormais « fuel_history absent/illisible » (`null`) de « historique vide mais valide » (`[]`, jour 1 du projet) : seul le premier cas déclenche `reconstructFuelHistory()` (nouveau `etl/src/history.ts`), qui recalcule les moyennes/jour depuis `rolling/30days` via DuckDB httpfs — logique extraite et partagée avec `bootstrap-og-history.ts` | Constaté en direct dans cette session : un run avec du code RPi périmé (sans le champ `fuel_history`) a effacé d'un coup les 27 jours amorcés plus tôt le même jour, en réécrivant tout `metadata.json`. Sans filet, ce scénario (RPi qui redrift, panne HF ponctuelle, JSON corrompu) redevient invisible pendant 7 jours minimum — inacceptable, Baptiste ne surveille pas ce point au quotidien | **Ne rien faire, laisser l'auto-guérison en 7-21 jours** : rejeté, correspond exactement au risque qui vient de se matérialiser sans supervision. **Réagréger `rolling/30days` à chaque run** (déjà écarté par [BDR-010](../decisions/BDR-010.md)) : toujours rejeté sur le run normal pour le coût RAM, mais devient acceptable en secours ponctuel puisque ce chemin ne s'exécute qu'en cas d'échec | actif  |
