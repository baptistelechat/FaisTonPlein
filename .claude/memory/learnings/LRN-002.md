# LRN-002 — TTL glissant 24h → invalidation quotidienne par date UTC

| Pattern observé                                                                                                                     | Contexte                                                                                                        | Application future                                                                                                                                       |
| ----------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Un TTL glissant de 24h (basé sur l'heure de mise en cache) désynchronise le cache local de la fraîcheur réelle des données publiées | Le rolling cache 30j de prix ne correspondait pas au rythme réel de publication des données (une fois par jour) | Préférer une invalidation par changement de date UTC (jour calendaire) plutôt qu'un TTL glissant quand la source se met à jour à un rythme fixe et connu |
