# LRN-006 — `$host` protège des tests, pas des collisions de noms d'events inter-app

| Pattern observé                                                                                                                                                                                                                                                                                                                                                                            | Contexte                                                                                                                                                                                                                                                                                                                                                     | Application future                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| L'insight "Funnel installation PWA" de FaisTonPlein affichait 1 personne alors qu'aucun vrai trafic n'existait — l'event `pwa_install_banner_shown` venait en réalité d'**ifecho** (`$host: ifecho.vercel.app`), pas de FaisTonPlein. Les deux apps utilisent le même nom d'event pour ce funnel (calqué intentionnellement sur le pattern ifecho, cf. [BDR-005](../decisions/BDR-005.md)) | Le filtre `$host` mis en place ([BDR-006](../decisions/BDR-006.md)) exclut le trafic de TEST (localhost) mais ne distingue en rien deux apps de PRODUCTION légitimes partageant le même projet PostHog — un nom d'event identique entre les deux mélange silencieusement leurs données dans n'importe quel insight qui ne filtre pas explicitement par `app` | Sur un projet PostHog partagé entre plusieurs apps, ajouter systématiquement un filtre `{key: "app", value: "<nom-app>", operator: "exact", type: "event"}` sur CHAQUE série d'event de CHAQUE insight — pas seulement sur les events dont le nom paraît à risque de collision. Vérifié en pratique : sur 23 events FaisTonPlein, 3 collisionnaient avec ifecho (`pwa_install_banner_shown`, `pwa_install_clicked`, `pwa_installed`) sans que ce soit anticipé à la création |

**Risque théorique additionnel identifié mais non encore matérialisé** : `$exception` (error tracking PostHog) est une capture native au niveau du SDK — si ifecho a aussi `capture_exceptions` actif, ses erreurs pourraient un jour apparaître dans l'insight FaisTonPlein "Erreurs par type". Le filtre `app` a été appliqué préventivement à cet insight aussi.

**Correctif appliqué** : les 19 insights du dashboard FaisTonPlein (`project 207198`, dashboard `944492`) ont été patchés via l'API PostHog pour ajouter ce filtre sur chaque `EventsNode` de chaque série — script Python en une passe plutôt que 19 éditions manuelles.
