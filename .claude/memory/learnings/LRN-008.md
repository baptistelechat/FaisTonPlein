# LRN-008 — Un seuil de staleness basé sur un cron doit avoir une marge, jamais être == l'intervalle nominal

| Pattern observé                                                                                                                                                                                                                                                     | Contexte                                                                                                                                                                                                                                                                                          | Application future                                                                                                                                                                                                                                                                     |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Un endpoint de santé qui compare `now - last_updated` à un seuil égal à l'intervalle nominal du cron qui produit `last_updated` déclenche un faux "degraded" à chaque cycle, en particulier si une couche de cache lit une valeur encore périmée juste après le run | Cas concret : [LRN-007](../learnings/LRN-007.md) — `/api/health` de FaisTonPlein avec `CACHE_MAX_AGE_MS` (2h) == fréquence cron ETL (`0 */2 * * *`), combiné à un `fetch` avec `revalidate: 300` (5min) qui pouvait encore renvoyer le `last_updated` du run précédent juste après le run suivant | Sur tout projet avec un job périodique (cron) + un check de fraîcheur qui lit une snapshot potentiellement mise en cache de sa sortie, la marge de sécurité doit toujours dépasser (jitter du cron + durée du cache de lecture amont), jamais être calée pile sur l'intervalle nominal |
