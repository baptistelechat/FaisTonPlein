# LRN-018 — Un bloqueur DNS local casse l'OAuth du MCP PostHog

| Pattern observé                                                                                                                                                           | Contexte                                                                                                                                                                                 | Application future                                                                                                                                                                                                              |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Le DNS du poste (`192.168.1.210`) répond `::` pour `oauth.posthog.com`, `mcp.posthog.com` et `app.posthog.com`, mais laisse passer `eu.posthog.com` et `eu.i.posthog.com` | En connectant le connecteur PostHog, le navigateur affichait `ERR_NAME_NOT_RESOLVED` sur la page d'autorisation. PostHog n'était pas en panne : les mêmes noms résolvaient via `1.1.1.1` | Devant un `ERR_NAME_NOT_RESOLVED` sur un service d'analytics, comparer `nslookup <hôte>` et `nslookup <hôte> 1.1.1.1`. Une réponse `::` en local signale le bloqueur : mettre l'hôte en liste blanche puis `ipconfig /flushdns` |

**À retenir :** `mcp.posthog.com` doit rester joignable pendant toute la session, pas seulement le temps de l'OAuth. Une liste blanche vaut donc mieux qu'une désactivation de cinq minutes.

**Sans effet sur les visiteurs :** l'ingestion (`eu.i.posthog.com`) n'est pas bloquée, et ce blocage ne concerne que le réseau de Baptiste.

**Constat annexe :** l'enregistrement du MCP PostHog en scope user (décision globale GBDR-010) n'existait plus dans `~/.claude.json` ce jour-là. La connexion est passée par le connecteur claude.ai.
