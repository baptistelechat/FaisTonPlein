# LRN-022 — Contenu généré dans un skill : paramètres côté projet et graine propre au projet

| Pattern observé | Contexte | Application future |
| --- | --- | --- |
| Dans un skill réutilisable, une table de variantes écrite en dur ou un tirage qui ne dépend que d'un index donne les mêmes sorties dans tous les projets. Pour que chaque projet ait les siennes, le moteur du skill ne doit contenir aucun contenu : ce qui donne le ton vient d'un fichier du projet, et le tirage part d'une graine propre au projet (son nom) combinée à l'index | Musique des vidéos `brag-series` : une table de 6 variantes puis un tirage sur le numéro de vidéo ont tous deux été refusés par Baptiste, parce que la vidéo N de chaque projet aurait eu la même musique | Avant d'écrire une liste de variantes dans un skill, se demander si deux projets doivent obtenir le même résultat. Si non : le skill décrit comment choisir les réglages, le projet les stocke, la graine inclut le nom du projet. Garantir l'unicité par le code (écarter ce qui est déjà pris) plutôt que de compter sur le hasard |
