# LRN-005 — COEP `require-corp` bloque silencieusement les analytics tiers

| Pattern observé                                                                                                                                                                                                                                                                                                                                                                                        | Contexte                                                                                                                                                                                                                                                                                                                                        | Application future                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Cross-Origin-Embedder-Policy: require-corp` (posé globalement dans `next.config.ts` pour activer `SharedArrayBuffer` côté DuckDB-WASM) bloquait silencieusement **toutes** les requêtes vers `eu.i.posthog.com` — aucune erreur applicative visible, juste un `net::ERR_BLOCKED_BY_RESPONSE.NotSameOriginAfterDefaultedToSameOriginByCoep` dans la console, et zéro event livré, en dev comme en prod | Découvert en testant l'intégration PostHog en local (bypass temporaire du guard localhost) : `posthog.capture()` s'exécutait sans erreur, posthog-js loggait bien `send "..."` en mode debug, mais aucune requête n'atteignait jamais PostHog — PostHog ne renvoie pas de header `Cross-Origin-Resource-Policy`, donc `require-corp` la rejette | Toujours vérifier qu'un service tiers (analytics, widgets, SDK externes) répond avec `Cross-Origin-Resource-Policy` avant d'activer `require-corp` sitewide. Préférer `credentialless` quand on a juste besoin de `SharedArrayBuffer` (WASM multi-thread) sans bloquer les ressources cross-origin no-cors — garde l'isolation nécessaire sans casser les intégrations tierces. Une intégration "qui compile et ne plante pas" n'est pas une preuve qu'elle fonctionne : vérifier via le réseau réel (Activity PostHog, pas juste les logs applicatifs) |
