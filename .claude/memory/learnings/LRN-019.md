# LRN-019 — `visibilitychange` seul : `beforeunload` en plus double le beacon

| Pattern observé                                                                                                                               | Contexte                                                                                                                                                                                  | Application future                                                                                                                                                                        |
| --------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| À la fermeture d'un onglet, `visibilitychange → hidden` et `beforeunload` tirent tous les deux. Brancher le même envoi sur les deux le double | `PostHogProvider.tsx` envoyait `session_ended` sur les deux. En prod, 9 visites sur 28 avaient deux events à moins de 300 ms d'écart, parfois à la même milliseconde, surtout sur desktop | Pour un envoi de fin de page, n'écouter que `visibilitychange`. Pour prouver un doublon, trier les horodatages d'un même event par `distinct_id` et chercher les paires quasi simultanées |

**Requête de preuve (HogQL) :** `groupArrayIf(toUnixTimestamp64Milli(timestamp), event = 'session_ended')` groupé par `distinct_id`. Avec `persistence: 'memory'`, un `distinct_id` correspond à un chargement de page, ce qui rend la lecture directe.

**Lecture des écarts :** quelques millisecondes = doublon de fermeture ; plusieurs secondes ou minutes = changements d'onglet légitimes.
